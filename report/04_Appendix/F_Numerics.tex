\chapter{Numerical Methods}\label{app:numerics}

This appendix collects the numerical-stability derivations and
mechanism specifications referenced from
Chapters~\ref{ch:introduction}, \ref{ch:methodology}
and~\ref{ch:discussion} and from Appendix~\ref{app:dag-formalism}.
Each section documents what the implementation actually does
(\texttt{StatisticsUtils}, \texttt{TaxonomyFitter},
\texttt{BtMatchScheduler}, \texttt{BtMmFitter}), not an idealised
variant.

\section{Log-Bessel Evaluation at High Dimension}\label{sec:num-bessel}

The vMF normaliser $C_d(\kappa) = \kappa^{d/2-1} / \left((2\pi)^{d/2}
I_{d/2-1}(\kappa)\right)$ requires the modified Bessel function
$I_\nu(\kappa)$ at order $\nu = d/2 - 1 = 127$ for $d = 256$, far
outside the range where direct series evaluation is stable.
The implementation evaluates $\log I_\nu(\kappa)$ by the uniform
(Debye-type) asymptotic approximation for large order: with
$z = \kappa / \nu$, $t = \sqrt{1 + z^2}$, and
$\eta = t + \log\!\left(z / (1 + t)\right)$,
\[
\log I_\nu(\kappa)
\approx \nu\,\eta
- \tfrac{1}{2}\log\!\left(2\pi\nu\right)
- \tfrac{1}{4}\log\!\left(1 + z^2\right),
\]
which is the leading term of the uniform asymptotic expansion of
$I_\nu(\nu z)$ and is accurate to well below the tolerance of any
routing or fitting decision for the $\nu$ used here.
For near-zero argument ($\kappa \leq 10^{-4}$), the small-argument
limit $\log I_\nu(\kappa) \approx \nu \log(\kappa/2) -
\log\Gamma(\nu + 1)$ is used instead, with $\log\Gamma$ evaluated by
the Lanczos approximation; in the same regime the vMF log-normaliser
falls back to the uniform-distribution surface term
$\log\Gamma(d/2) - (d/2)\log\pi - \log 2$.
The Bessel ratio required by the concentration MLE
(Appendix~\ref{app:dag-formalism}),
\[
A_d(\kappa) = \frac{I_{d/2}(\kappa)}{I_{d/2-1}(\kappa)}
= \exp\!\left(\log I_{d/2}(\kappa) - \log I_{d/2-1}(\kappa)\right),
\]
is computed as the exponential of the difference of two log-Bessel
evaluations and clamped to $[0, 1]$, its analytic range.
The same ratio's derivative,
$A_d'(\kappa) = 1 - A_d(\kappa)^2 - \tfrac{d-1}{\kappa} A_d(\kappa)$,
drives the Newton--Raphson refinement of
$\hat{\kappa}$ described in Appendix~\ref{app:dag-formalism}.

\section{NiW Posterior Update and Student-$t$ Predictive}\label{sec:num-niw}

Each node stores a diagonal Normal-inverse-Wishart posterior over its
member embeddings (weighted by the trickle weights $w_i$ with
effective count $n = \sum_i w_i$).
The prior is
$m_0$ = the parent's vMF centroid (the first
basis vector at the root), pseudocount $\kappa_0 = 1$, degrees of
freedom $\nu_0 = d + 2$, and scale
$\boldsymbol{\Lambda}_0 = \lambda_0 \mathbf{I}_d$ with $\lambda_0 =
1/(\kappa_{\text{parent}}\, d)$, where $\kappa_{\text{parent}}$ is
the parent-anchored prior concentration.
With weighted sample mean
$\bar{\mathbf{x}} = \tfrac{1}{n}\sum_i w_i \mathbf{x}_i$, the
conjugate updates are
\[
\kappa_N = \kappa_0 + n,
\qquad
\nu_N = \nu_0 + n,
\qquad
m_N = \frac{\kappa_0 m_0 + n \bar{\mathbf{x}}}{\kappa_N},
\]
and, per coordinate $j$ (the implementation stores only the diagonal
of the scale matrix),
\[
\Lambda_{N,j}
= \lambda_0
+ \sum_i w_i \left(x_{ij} - \bar{x}_j\right)^2
+ \frac{\kappa_0 n}{\kappa_N}\left(\bar{x}_j - m_{0,j}\right)^2 .
\]
The corresponding posterior predictive is a multivariate Student-$t$
with $\nu_N - d + 1$ degrees of freedom, location $m_N$, and (diagonal)
scale $\boldsymbol{\Lambda}_N (\kappa_N + 1) / (\kappa_N (\nu_N - d +
1))$.
In the current implementation this predictive is not used for routing,
which is vMF-based (Appendix~\ref{app:dag-formalism}); the stored
posterior serves
diagnostic roles, notably the leaf log-semantic volume
$\sum_j \log \Lambda_{N,j}$ tracked by the convergence stabiliser.

\section{KDE Bandwidth for the Scheduler Valley Weight}\label{sec:num-kde}

The match scheduler's density-aware pair weight rewards pairs whose
score midpoint falls in a low-density region of the current
Bradley--Terry score distribution.
Given the $n$ current scores with sample standard deviation
$\hat{\sigma}$, the kernel bandwidth follows Silverman's rule of
thumb for Gaussian kernels,
\[
h = 1.06\, \hat{\sigma}\, n^{-1/5},
\]
floored at $10^{-4}$; the density at a pair's midpoint
$m = (s_i + s_j)/2$ is the Gaussian kernel density estimate
\[
\hat{f}(m) = \frac{1}{n h \sqrt{2\pi}}
\sum_{k=1}^{n} \exp\!\left(-\frac{(s_k - m)^2}{2h^2}\right),
\]
normalised by the maximum density attained at any score point, and
the valley weight is $1 - \hat{f}(m)/\hat{f}_{\max}$, floored at
$0.1$ so no pair is fully suppressed.
Two gap-based guards precede the density term: a pair whose score gap
exceeds $4(\hat{\sigma}_i + \hat{\sigma}_j)$ is suppressed entirely
(already decided), and a pair below the noise floor
$0.15(\hat{\sigma}_i + \hat{\sigma}_j)$ is linearly ramped
(indistinguishable at current precision).

Every guard above is keyed to $\hat{\sigma}$, so this machinery
degenerates wherever the standard errors do. In the withdrawn runs
that predate the variance fix the stored standard errors were floored
or understated (Section~\ref{sec:meth-bt}), which made the gap guards
close to constant thresholds; in the worst case the resulting
allocation concentrated on a leader-centric star covering under a
third of the comparison graph. This valley machinery belongs to the
legacy utility-blend selection path that those withdrawn runs used;
the settled runs select pairs by the rank-adjacency rules of
Section~\ref{sec:app-scheduler} and do not consult it. It is
documented here because the withdrawn runs' behaviour is explained by
its degeneration.

\section{Observed Fisher Information for BT Standard Errors}\label{sec:num-fisher}

The Bradley--Terry log-likelihood over pairs with comparison counts
$n_{ij}$ and win probabilities
$p_{ij} = \sigma(s_i - s_j)$ has observed information matrix
\[
\mathcal{I}(\mathbf{s})
= \sum_{i < j} n_{ij}\, p_{ij} (1 - p_{ij})\,
(\mathbf{e}_i - \mathbf{e}_j)(\mathbf{e}_i - \mathbf{e}_j)^\top,
\]
i.e.\ $\mathcal{I}_{ii} = \sum_{j \neq i} n_{ij} p_{ij}(1-p_{ij})$
and $\mathcal{I}_{ij} = -\,n_{ij} p_{ij}(1-p_{ij})$, evaluated at the
MM fixed point $\hat{\mathbf{s}}$ (Section~\ref{sec:num-bt-estimator}).
$\mathcal{I}$ is singular with rank deficiency one (row sums vanish),
reflecting the additive-constant non-identifiability that the
zero-sum constraint $\sum_i s_i = 0$ removes.
The implementation resolves the singularity by inverting the
rank-completed matrix $\mathcal{I} + \mathbf{1}\mathbf{1}^\top$
(Gauss--Jordan with partial pivoting) and recovering the
constrained covariance as
\[
\operatorname{Var}(\hat{s}_i)
= \left[(\mathcal{I} + \mathbf{1}\mathbf{1}^\top)^{-1}\right]_{ii}
- \frac{1}{K^{2}},
\]
where $K$ is the number of models. Adding $\mathbf{1}\mathbf{1}^\top$
is equivalent to imposing the sum-to-zero constraint, and the
subtracted term removes the artificial variance the completion
introduces along the constrained direction.

\paragraph{The correction term is $1/K^{2}$, and an earlier version of
this system used $1/K$.}
Write the completed matrix as $F_c = F + J$ with $J = K \cdot P$ and
$P = \mathbf{1}\mathbf{1}^\top\!/K$ the projector onto the constrained
direction. Then $F_c \mathbf{1} = K \mathbf{1}$, and inverting on the
two complementary subspaces gives
$F_c^{-1} = F^{+} + J/K^{2}$, so the term added by the completion ---
and therefore the term to subtract --- is $1/K^{2}$.
Subtracting $1/K$ instead over-subtracts $(K-1)/K^{2}$, which is
$0.109$ at $K = 8$ and exceeds the variance itself at most realistic
comparison counts. Where it does, the variance goes negative and the
standard error is clamped at the floor of $0.01$; where it does not,
a positive but understated value is reported. No value computed under
the wrong constant is a measurement either way. In the pilot run,
$45$ of $176$ stored per-node standard errors sit exactly at the floor
and the rest have a median of $0.09$; correct values are 44 to 209
times larger. The consequence
for what may be quoted is stated in
Section~\ref{sec:disc-debt}.
If the completed matrix is numerically singular, the implementation
falls back to the diagonal approximation
$\operatorname{Var}(\hat{s}_i) \approx 1/\mathcal{I}_{ii}$.
Reported standard errors are
$\hat{\sigma}_i = \sqrt{\operatorname{Var}(\hat{s}_i)}$, floored at
$0.01$. Because comparisons sharing a query are treated as
independent, these standard errors underestimate the true uncertainty
by a margin this thesis does not measure
(Section~\ref{sec:meth-assumptions}).

\paragraph{The scheduler consequence of the pre-correction values.}
Demoted from Section~\ref{sec:disc-debt}, which keeps the verdict.
The terms below ($U_{\text{resolve}}$, the mixing weight $\alpha$,
the $3\sigma$ resolve rule) are the legacy utility-blend scheduler's
own quantities --- the selection path Runs~A and~B used, which the
settled runs replace with the rules of
Section~\ref{sec:app-scheduler}. Runs~A and~B consumed standard
errors that were floored for about a quarter of nodes and understated
for the rest, with three likely mechanical consequences: the variance
division inside $U_{\text{resolve}}$ degenerated toward a constant,
so the term
approached pure entropy; the maturity-driven mixing weight $\alpha$,
keyed to falling per-leaf standard errors, did not mature as designed;
and the $3\sigma$ resolve rule tended toward a fixed margin
$|\hat{s}_i - \hat{s}_j| \geq 0.06$. Section~\ref{sec:num-kde} traces
the same degeneration through the pair-weight gap guards.

\section{Persistence Stores and the Run Manifest}\label{sec:num-persistence}

The storage detail below is demoted from Section~\ref{sec:arch-infra};
the seed semantics and the rebuild check stay there.

State is partitioned across four SQLite stores with distinct write
lifecycles: the embedding cache, the MMLU-Pro corpus with its per-model
stored evaluations, the snapshot store, and the ratings store. Only
frozen snapshots are eligible as arena inputs and a frozen snapshot is
read-only, and every verdict row carries the snapshot identifier, so
the taxonomy a verdict was produced under is always recoverable.

Per-run seeds and realised call counts are recorded in a manifest
emitted with each run. Two qualifications belong with that claim. The
manifest's working-tree-clean flag does not distinguish a modified
source file from a modified thesis file, so it fires on benign
conditions and should not be read as a reproducibility guarantee on
its own. And \texttt{ratings.db} is keyed by snapshot and condition in
a way that makes a re-run of the same condition \emph{clear} the
previous rows rather than accumulate beside them; the results of
Chapter~\ref{ch:results} were preserved by copying the store before
each subsequent run.

\section{The Bradley--Terry Estimator and Prior}\label{sec:num-bt-estimator}

Section~\ref{sec:meth-bt} keeps the model, the tie convention, and
the standard-error correction. Nothing here is new; the choices are
standard and are recorded for exactness.

The estimator is the Minorisation--Maximisation update of
\textcite{hunter2004mm}, an iterative scheme that maximises a simple
lower bound on the likelihood at each step, written in the
exponentiated parameters $\pi_i = e^{s_i}$:
\[
\pi_i^{(t+1)} \;=\;
\frac{W_i}{\displaystyle\sum_{j \neq i}
\frac{N_{ij}}{\pi_i^{(t)} + \pi_j^{(t)}}},
\qquad W_i = \sum_{j \neq i} W_{ij},
\]
applied as a simultaneous (Jacobi) sweep over all models. Iteration
stops at a tolerance of
$\max(10^{-6},\, 0.01\,\widehat{\mathrm{SE}}_{\text{lb}})$ or at a cap
of 200 sweeps.

A Jeffreys prior is applied on top of the counts. The Jeffreys prior
for a binomial probability is the $\mathrm{Beta}(0.5, 0.5)$
distribution, the standard uninformative choice; adding it here amounts
to giving a pair half a phantom win in each direction before the fit
runs. Its purpose is to keep a fitted win probability away from $0$ and
$1$ when one model has swept a pair, which is the case where the
likelihood has no interior maximum and the strength difference would
otherwise run off to infinity.
It is applied only to pairs that already carry at least one real
comparison. Pairs with no data are left untouched, so the prior
regularises estimates rather than manufacturing edges in the comparison
graph, and the identifiability check runs on the observed counts alone.

\section{Scheduler Mechanics}\label{sec:app-scheduler}

Section~\ref{sec:meth-scheduling} keeps the loop overview and the two
properties results depend on; the rules below are the loop's full
specification, and where an earlier rule was replaced, the
replacement's reason is recorded with it.

\paragraph{The bootstrap floor.}
Before any adaptive scheduling, every (cell, pair) slot receives one
comparison. The floor is per (cell, pair) rather than global. A global
floor --- one comparison per pair anywhere in the domain --- leaves the
domain-level comparison graph complete while individual cells stay
sparse, and every per-cell quantity in this thesis rests on those
per-cell graphs. One comparison per pair per cell is enough to make
each cell's graph complete rather than merely connected, which is what
per-cell estimation needs, and it costs $\text{pairs} \times
\text{cells}$ calls: 308 at eight models and eleven cells. Bootstrap
tasks round-robin over cells so a run stopped early has balanced
coverage, and the query is rotated across the cell's pool by a
per-cell offset, so consecutive bootstrap tasks take consecutive
questions instead of all 28 pairs judging the same one. When the
bootstrap completes, an assertion checks that no model has zero
comparisons and aborts rather than fitting an unidentified ranking.

\paragraph{Batch quotas.}
Each round has a batch size, and each cell's quota within it is
proportional to that cell's held-out pool size, floored at one so no
cell is starved out of a batch entirely. Equal-per-cell allocation was
the earlier rule and it distorted the domain estimate: on physics each
of the ten cells took $9.2$ to $11.3\%$ of the comparisons while
holding $5.6$ to $17.8\%$ of the questions. That is defensible for a
per-cell fit, whose cost does not scale with cell size, and wrong for
the domain fit, which pools sufficient statistics and therefore weights
a cell by its comparison count. When quotas are filled and the batch is
not, the batch comes back short: topping it up from whichever cell
still has work would re-introduce exactly the over-weighting the
quotas remove.

\paragraph{Choosing a pair and a query.}
Within a cell, models are ordered by their current fitted
Bradley--Terry strengths and only rank-\emph{adjacent} pairs are
sampled. Adjacent pairs are the closest by construction, so they are
where an extra comparison can still change the order; a pair separated
by several places is already decided. Among the adjacent pairs the
scheduler takes the one whose confidence interval still straddles a
coin flip by the widest margin. Ordering on fitted strengths rather
than on summed win rates matters early in a run, when most pairs carry
one comparison and a win-rate order is dominated by coin flips, which
makes the adjacency set churn between rounds.
The query is then chosen inside that pair by two rules. Queries where
the two models gave \emph{different} stored answers are preferred,
because a comparison in which both models answered identically carries
little signal. Among those, the query judged fewest times anywhere in
the cell is taken, with ties broken by query identifier so the
selection is deterministic at a fixed seed. The least-used rule spreads
a cell's budget over its pool; the earlier rule, lowest unused
identifier per pair, let all 66 pairs in a cell converge on the same
handful of questions.

\paragraph{When a pair is finished, and when the run is.}
A pair is terminal inside a cell under any of three conditions.
An \emph{exact two-sided binomial test} of that pair's within-cell wins
against $p = 0.5$ rejects at $\alpha = 0.05$ after Bonferroni
correction over the $M - 1$ adjacent pairs actually tested, with a
minimum of five comparisons. Ties enter the test at half weight and are
rounded to the nearest whole win count, which pushes the statistic
toward $n/2$ and away from significance.
Or its \emph{per-(cell, pair) budget} is spent. That budget is sized
from the cell's own pool, $\lfloor n/4 \rfloor$ clamped to $[8, 25]$,
so a large cell is not rationed by the smallest cell in the domain. The
floor of 8 keeps the binomial test reachable --- a pair one model wins
outright resolves at 9 comparisons under the Bonferroni correction ---
and the ceiling of 25 stops a large cell spending budget on a pair
already decided.
Or the \emph{confidence gate} retires it. At the start of every round
each cell's pairs are tested against that cell's own $\theta$ and
standard errors, and a pair is retired in that cell when
$|\theta_i - \theta_j| > 2.5\max(\sigma_i, \sigma_j)$. The gate is
keyed \texttt{cell|modelA|modelB} and is recomputed from scratch each
round. It used to be keyed on the pair alone and fed from the pooled
leaderboard, which retired a pair in every cell at once on the strength
of the pooled result --- that assumes the null the per-cell arena
exists to test, and Section~\ref{sec:res-runs} reports what it did to
one run.

A run ends when the round counter reaches its cap, when a size-weighted
$70\%$ of cells are converged, or when the scheduler returns an empty
batch because every pair is terminal or budget-exhausted. Which of
these ended each run is recorded with the run.

\section{Design-Document Mechanisms with No Implementation}\label{app:not-implemented}

The sections above document what the implementation computes; this one records
what it does not, because several mechanisms are natural to assume from
Chapter~\ref{ch:methodology} or appear in earlier design documents for this
system. None exists, and no result in this thesis depends on any of them
(Section~\ref{sec:meth-not-implemented}).

Three of the absences would change how a reader reads a number, and are stated
in full. \textbf{$1/k$ fractional weighting of multi-leaf queries} is not
applied: the propagation path receives only a query's primary leaf and adds
weight $1.0$. A post-hoc analysis computing membership posteriors exists, but it
is a different quantity from what a $1/k$ convention would produce, so the two
are not a sensitivity pair. \textbf{Judge Cohen's $\kappa$ and a verbosity delta
$\Delta_{\text{verbosity}}$} are computed nowhere; what is measured instead is
the dual-call agreement rate, the tie rate by stratum, and the response-format
analysis of Section~\ref{sec:res-capture-gap}. \textbf{Query selection within a
scheduled pair} is a persisted round-robin offset over the leaf's pool, not a
cosine ordering (Section~\ref{sec:meth-scheduling}).

The remainder are naming or bookkeeping differences with no effect on any
reported quantity: there is no per-leaf arena state object with a response cache
(responses are not generated during a run, so there is nothing to cache);
standard errors are initialised to $10.0$ rather than to infinity; the named
per-pair and per-leaf state machines and the utility floor $U_{\min}$ do not
exist, only the resolution predicate of Section~\ref{sec:meth-scheduling}; the
global escape valve at $B_{\max}$ is in fact the round cap; and no
temperature-scaling calibration of routing confidences is applied.
