\section{Total Dasgupta Cost}\label{sec:app-metrics-dasgupta}

% Compressed 2026-07-31: uncited in chapters; full text in this file's history.
The pipeline exports the standard whole-tree cost
$\text{cost}(T) = \sum_{i \neq j} w_{ij}\,|\text{Leaves}(\text{LCA}_T(i,j))|$
with $w_{ij} = \max(x_i^\top x_j, 0)$ \parencite{dasgupta2016cost}; lower is
better. It is distinct from the per-split acceptance test of
\S\ref{sec:meth-split}, which is not a Dasgupta quantity.

\section{Leaf Purity, Flat and LCA-Sensitive}\label{sec:app-metrics-wlp}

% Compressed 2026-07-31: uncited in chapters; full text in this file's history.
The pipeline exports a complementary purity pair against the MMLU-Pro
ground-truth labels: Weighted Leaf Purity, the leaf-size-weighted mean of
per-leaf majority-label fractions, and standard Dendrogram Purity over the
tree's unique LCAs (Section~\ref{sec:poly-negative}). WLP flat-tests each leaf;
Dendrogram Purity additionally penalises same-label pairs split across distant
subtrees.

\section{Average Match Count}\label{sec:app-metrics-avgmatch}

Routing is weighted multi-membership even though the taxonomy is a strict tree,
so a query can be assigned to more than one leaf. Writing $\mathcal{L}(q)$ for
the set of leaves query $q$ reaches,
\[
\text{AvgMatch} = \frac{1}{N} \sum_{i=1}^{N} |\mathcal{L}(q_i)|.
\]
$\text{AvgMatch} = 1.0$ means routing resolves every query to a single leaf;
above $1.0$ it measures how much multi-membership the routing beam and the
membership floor actually produce
(Appendix~\ref{app:dag-formalism}, \S\ref{sec:meth-routing}).

On the frozen tree the construction corpus gives $9{,}141$ leaf memberships over
$8{,}299$ unique queries, so $\text{AvgMatch} = 1.101$
(Appendix~\ref{app:frozen-tree}). This quantity governs the construction corpus
only: the arena withdraws secondary memberships before scoring, so a routed
held-out query contributes to exactly one cell.

\section{Routing Expected Calibration Error}\label{sec:app-metrics-ece}

Routing ECE tests whether the soft-routing distribution's confidence is
calibrated against its accuracy, at \emph{domain} granularity. For each query,
its normalised leaf membership weights are aggregated onto each leaf's depth-1
domain ancestors, yielding a per-query distribution over domain categories in
the same label space as the MMLU-Pro category strings; the query's
\emph{confidence} is the maximum domain mass, and its prediction is correct when
that argmax matches the query's category. Queries are grouped into $B$
equal-width confidence bins, and
\[
\text{ECE} = \sum_{b=1}^{B} \frac{|\mathcal{B}_b|}{N} \left| \text{acc}(\mathcal{B}_b) - \text{conf}(\mathcal{B}_b) \right|.
\]
No temperature-scaling recalibration is applied anywhere in this system.

\textbf{The exported number is not this metric.} The definition sums a query's
leaf membership onto each leaf's depth-1 domain ancestor, which is what makes
the result a distribution over domains. The export path instead takes the
\emph{maximum} over a domain's leaves, and a maximum over leaves is not a
distribution: it does not normalise, and it systematically understates
confidence for queries spread across several leaves of the same domain. The
frozen run's exported $0.2114$ is therefore a diagnostic with the discrepancy
named, and no claim in this thesis rests on it
(Section~\ref{sec:disc-debt}). The direction of the error is known and its size
is not: fixing the aggregation raises every confidence, so apparent
under-confidence falls, by an amount nobody has measured. This is the full
statement of the defect; the other places it is mentioned point here.
