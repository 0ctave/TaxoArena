## Patterns to copy (they are the record's)
- A new engine knob = a TOML key parsed fail-closed (`toBooleanStrictOrNull` / explicit enum, unknown value fatal, message naming the key), a cross-check in `HeadlessCliConfig.init` (e.g. refused without `runPipeline`, with `unionSnapshots`), a manifest field via `DiagnosticsBundle.record...`, a warn line at the apply site, and an INERTNESS test in the pattern of `ConstructionOrderInertnessTest` / `AnchorFreeInertnessTest` (golden DAG hash when the flag is absent; a non-vacuous assertion when it is on, e.g. "the root split was ACCEPTED with positive dJ").
- A new analysis script = docstring with the registration and launch sequence; `pool_guard.assert_pool_of_record(<pool id>)` printed first; `--dry-run` assembles everything and posts nothing; `--pilot N` read by a truncation guard that REFUSES above 5% unparsed on the deciding subset; own cache with meta pinned at first launch (judge, cap, temperature, protocol, set hash, script sha) and a refusal on mismatch; resumable; errors never cached except deterministic refusals (`content_filter`, cached as unusable rows); `--analyze` that writes the file of record only from a complete cache and a `_PILOT` / `_partial` file otherwise; every judge call through `rr.call_judge_full`; any local body copy asserts against `rr.payload_body`'s source.
- Readouts: name the denominator, wrong(established), both tie conventions, question-clustered bootstrap, predictions scored, and the measured support beside the deciding statistic (DEFF from the cache's own cluster sizes, n_eff, MDE; the pattern is `support_readout` in `ifeval_response_oracle.py` L511-L533).
- Outcome files of record are WRITE-ONCE: open with mode `x`, or refuse when the path exists (`canary_baseline.py --analyze` opened `"w"` and a re-run would have wiped inserted corrections; pass-2 review defect 2). Every registered criterion, prediction and falsifier has a print branch that a SELFTEST EXECUTES: `topic_partition.py` L1061 `if c2 is True:` never fired because the value was `numpy.bool_`, and the C2 sentence of record was lost from a file that cannot be repaired (TOPIC-PARTITION-20NG D1; D7: the falsifier lines were never printed at all). Never identity-test a computed value — `bool(...)`.
- Pin a script's identity by its LF sha (`git hash-object`), naming the rendering; the CRLF working-tree sha goes beside it, never instead of it (ARM-B-VINTAGE D1).

## Value-asserting end-to-end tests on deciding paths (the recurring defect)
Reviewers' mutants keep surviving because selftests exercise helpers, not the path that decides. Before handing over:
1. For EVERY deciding path (each registered criterion / prediction / falsifier branch, each refusal or gate, each mode the run of record uses, e.g. `--run` / `mode_run` / `--analyze`), a selftest that EXECUTES the real entry point on a fixture whose correct answer you know, and asserts the printed VALUE (the number, the verdict word, the refusal), not that a line exists or that it ran.
2. Kill the mutant classes that survived in this session's READY reviews, where they apply: min↔max; first-site-only vs all sites; zero sites / empty input; root or boundary region; wrong split side (R on TRAIN instead of EVAL, C1 from the wrong population); a p-value or denominator changed from the registered form (RP06 X3: p = k/300); a skip or Assumption path that omits a required printed line; an uncapped fork (bb30526 RP08 X1/X2/X6/X8; 1adce88 RP11 X4/X12, mode_run unexercised; 114f80f RP06 X3; 7676eab RP07 H1/H2).
3. Run those mutants yourself (temporary edits, reverted) and record them in the selftest docstring or commit message as a table: mutant, killed/survived. A survivor on a deciding path is yours to fix before the handover.

## How you work
1. Work in the worktree the orchestrator gives you (confirm `git rev-parse --show-toplevel`; `git merge --ff-only main` first if it is behind). Never in the main checkout unless told.
2. Plan first (files, functions, tests, risks to bit-identity and pool hygiene), then implement exactly that; deviate only where the code forces it and say so. Refuse to build to a registration with no Support section, or whose criteria can fire two verdicts on the same data: report it to the registrar rather than resolving it in code (BFCL-JUDGED-PILOT C1 was resolved silently in the write-out and became criterion substitution; ruling at programme L11994-L12029).
3. Run the targeted tests, then the full suite; in a worktree the ONLY acceptable failures are MrlRoutingTest.testMrlConfigDefaults and TraceEnvelopeUnwrapTest blank-trace (they need the uncommitted application.yml / production DBs). Anything else is yours to fix.
4. Never write to `experiment_results/**/*.db`, `snapshots_frozen.db`, `embeddings_cache.db`, `mmlu_pro_dataset_cache_v2.db`, `multicorpus_cache_v1.db`; open them `mode=ro` (and `immutable=1` for WAL-mode engine DBs). Never copy production DBs into a worktree.
5. Commit on the worktree branch with explicit paths (`git add <files>`; `git commit -q -F <msgfile> -- <files>`), message ending with the session's attribution lines; never stage `*.db`, `logs/`, `application.yml`, `.env`, `.gitignore`. Leave the branch for the reviewer and the orchestrator's merge.
6. Edits to any record file (programme, ledger, FRAMEWORK.md, plan) are insertion-only brackets; a docstring's registered sentence is a record too.

## Never
Write, move or delete a path in the MAIN checkout without `git ls-files --error-unmatch <path>` first (a helper script copied into main and then deleted was tracked, and needed `git checkout --` to recover); stage with `git add -A` / `git add .`, or commit without `-- <paths>` (the index is shared with other agents, so a peer's staged files land in your commit); post a judge call; run a full construction, site null or judged run unless told; change a prompt or the reference wrapper as a side effect; renumber or reword a registered criterion; leave a flag that is not provably inert when absent.

## Report format (the hand-back; about 150-250 words)
VERDICT/STATE (built / blocked, one line) · COMMITS (branch + tip sha) · NUMBERS OF RECORD (tests passed/failed with the two allowed failures named, mutants killed n/m, the inertness discriminator) · BLOCKERS / CONDITIONS (deviations from the plan, registration defects handed to the registrar) · AUTHOR DECISIONS NEEDED · FILES. Function-level changes, test tails, pins and the mutant table go in the commit message / selftest docstring, not the hand-back.

## Deliverable
Worktree, branch, commit (its message carries the files with function-level changes, test tails, the inertness proof, the mutant table, what is not done and why) and the short hand-back above.
