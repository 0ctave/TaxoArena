## 1. A9 MODEL-VINTAGE-CANARY (registered DEFINITION and rule; zero judge calls; contestant generation only)

Question. The record has no test for a contestant whose NAME is constant and whose weights or serving stack change
(FRAMEWORK mentions drift only for the judge and the reference: guard 19 "the existing canary sees judge drift only"
[FW L245]; nothing on contestants). Every verdict of record was posted on FROZEN answer text (eval_results
model_output), so a drifting model cannot change any existing verdict; what it changes is whether a row may still be
called by that model's name. A9 defines when it may not.

Definition (the rule). Model drift = ANSWER-CONTENT drift on the canary question set: the 279 distinct questions of
the CANARY-BASELINE set (hash 50af669ac6997f9f; not the 300 matches - the object is per-model, so every roster model is
regenerated on all 279, giving n_m = 279 per model, 278 for iask_pro, rather than the 16-94 questions a model has in
the matches). For roster model m, vintage v0 = the cached eval_results rows; vintage v1 = a fresh generation under a
RECORDED protocol P = (harness prompt bytes, sampling setting, max_tokens, provider, deployment fingerprint, extractor
version); agreement a_m = share of the 279 questions on which extract(v1) == extract(v0). The extractor is one
versioned function applied to BOTH the cached model_output and the new output (extract-v1); before any generation
the extractor must reproduce the cached `pred` column at >= 0.99 per model (zero-cost pre-check; if it does not, the
extractor, not the model, is the object - the CHECKER-ANSWER-INGEST lesson of three readings of one table).

Null, read FIRST on fixed checkpoints (the REF-SC analogue). Seven roster models are published weights and therefore
fixed checkpoints: Llama-2-7b-hf, Llama-2-13b-hf, Meta-Llama-3_1-8B, Meta-Llama-3_1-70B-Instruct, Qwen1.5-72B-Chat,
Yi-6b-Chat, c4ai-command-r-v01. Two floors are read on them under P, and both are printed per model and pooled:
  F_gen = agreement between two generations of the same checkpoint under P (the sampling floor; the TEMP-0 analogue:
          for the judge, temperature 0 left 82% of responses different in wording and the verdict flip rate
          unchanged, 0.050 vs 0.057 [LEDGER TEMP-0], so a greedy setting is expected to raise F_gen for open weights
          but is not assumed to reach 1.0);
  F_cache = agreement between v1 and the cached v0 of the same checkpoint (the harness + extractor + sampling floor:
          the cached vintage's harness is not on record, so F_cache bounds what "agreement with the cached vintage"
          can mean for ANY model, including the API ones).
The alarm floor is F = pooled F_cache over the fixed checkpoints (question-weighted), with its per-model spread. If the
per-model F_cache spread exceeds 3 SE of the pooled value, the null is UNDETERMINED and NO alarm fires this pass (a
registered outcome), because the cached rows were then not produced under one harness.

Alarm rule. Model m alarms iff a_m < F - 3 x sqrt(F(1-F)/n_m). At the REF-SC point F = 0.94, n = 279 the threshold is
0.897 (SE 0.0142, 3 SE = 4.3pp); at F = 0.90 it is 0.846. One-sided; read per model; never pooled across models.
Secondary, DESCRIPTIVE, never the alarm: accuracy delta of m on the 279 keyed questions (exact McNemar v1 vs v0),
which separates directional drift (accuracy moved) from re-sampling (accuracy flat); per-anchor agreement printed
(14 anchors x ~20 questions) as description only.

Consequence (guard 12 extended by insertion). A model below the alarm is a NEW VINTAGE m@v1: it re-enters through the
online-operation path as a new model (keyed cells 0 calls; ~800 cce to a band, ~3,100 cce for profile coverage
[LEDGER NEWCOMER-PLACEMENT-LIVE; leads/data_economics.md §6]); its v0 rows stay published under the v0 label with the
answer-table hash; v0 and v1 verdicts never share a fit (guard 12 [FW L238], extended to contestant vintages). A model
above the alarm keeps its rows and gets the stamp "vintage v0 confirmed at a_m on 279 q, pass k". Every eval_results
row used by a board carries, forward-only, (model_name, vintage_id = sha of the model's answer column, harness_id,
sampling, max_tokens, fingerprint, extractor_version); the legacy rows get vintage_id only, with the other fields
UNSTAMPED (the FW L37 pattern for the reference cache).

Hygiene. EVAL side only (the 279 are pool p2dca21ab5f4ef3ae questions [LEDGER CANARY-BASELINE]); the canary set is
loaded and hash-verified, never re-frozen; the reference is NOT re-minted by this arm (that is arm B / C2); no judge
call is posted (a_m is computed at ingest); Meta-Llama-3-70B-Instruct excluded (asserted absent); contestant
sampling setting RECORDED per generation (the D2 analogue: what the judge does with "temperature omitted" the
contestant does with an explicit literal or an explicit "omitted"); output cap recorded; finish_reason recorded, a
capped generation is NON_TERMINATED and is neither an agreement nor a disagreement (kept in the denominator print,
excluded from a_m's numerator and denominator, and refused above 5% per model - rule 10).

Cost. Judge: 0. Contestant generation, per model, from the cached vintage's own output lengths on the 279 questions
(mean chars per answer, eval_results, command in §4; tokens ~ chars/4 x 279; input side = harness prompt x 279, NOT on
record because the DB stores no prompt - a 5-shot CoT harness is of order 1.5-2.5k tokens per question, an outside
estimate, not a record number):
  Llama-2-7b-hf 311 ch -> ~22k out; Llama-2-13b-hf 329 -> ~23k; c4ai-command-r-v01 371 -> ~26k; Yi-6b-Chat 420 ->
  ~29k; Meta-Llama-3_1-70B-Instruct 489 -> ~34k; Qwen1.5-72B-Chat 509 -> ~35k; Meta-Llama-3_1-8B 635 -> ~44k;
  gemini-3.1-pro_5-shots 870 -> ~61k; arx_0314 888 -> ~62k; deepseek-chat-v2_5 1,020 -> ~71k; iask_pro 1,257 ->
  ~87k (278 q); gpt-4o-2024-08-06 1,512 -> ~105k. Roster total ~0.6M output tokens per pass; the null costs a second
  generation on the 7 fixed checkpoints (~0.21M more). Open weights are local GPU time if the author hosts them.

Criteria. (C1) extractor pre-check >= 0.99 per model. (C2) F_gen and F_cache read on >= 5 of the 7 fixed checkpoints
with per-model spread inside 3 SE (else UNDETERMINED). (C3) per-model a_m with interval and the alarm decision. (C4)
the accuracy delta beside it.
Predictions. F_gen 0.95-0.99 at a greedy setting, 0.88-0.96 at default sampling, lower for the low-accuracy small
models (Llama-2-7b, Yi-6b: near-chance answers re-sample freely); F_cache 0.85-0.95 (harness change is the larger
term); gpt-4o-2024-08-06 (a dated snapshot) inside the null; among the undated API rows (gemini-3.1-pro, arx_0314,
iask_pro, deepseek-chat-v2_5) at least one below the alarm (low confidence: the first model-drift reading in the
record). Falsifier of the DEFINITION: F_cache pooled below 0.80 on the fixed checkpoints, i.e. the cached vintage
cannot be re-attached to any harness, in which case the definition degenerates to "every model is a new vintage on
its first regeneration" and the rule must be re-registered on a v1 baseline (two generations under P, then drift
read against v1 in later passes).
Undetermined and stated: the null itself (never read; REF-SC's 0.94 is a two-prompt figure for a different object);
the harness of the cached vintage; whether API providers expose a reproducible sampling setting at all; the MDE - at
n = 279 and F = 0.94 a one-sided 3 SE alarm with 80% power sees an agreement loss of ~6pp, so a 3pp drift is
invisible in one pass (the judge-canary analogue: MDE ~2.7pp at n = 300 [FW L141]); pooling passes across epochs
(three passes ~840 paired questions) is the only route below that and is a later registration.
Closed-lines check: touches no reference, rubric, gating, ensemble or temperature-of-the-judge line; introduces no
reference; the disagreement filter and the judge are untouched.

## 2. A10 AGENT-CORPUS-ADMISSION (registered ADMISSION TEST; a corpus passes it BEFORE any judged spend; 0 calls)

Object. An agent corpus = (task, agent) episodes with a tool log and a final state. It is admitted to the pipeline
as-is only if the five parts below are verified BY COMMAND on the ingested tables, then a checker pilot is read.
Failure of any part is a refusal, not a warning (the CONTEXT rule-2 shape).

(a) SPLIT. Per item: stem + content_key under SplitSide norm-v1, side = f(item) asserted per row in both languages
    (GATE = hash in [300, 400)) [LEDGER SPLIT-FUNCTION-IMPL]; family_id write-once for templated or parameterised
    tasks so a family sits on ONE side; the pool id exported as a file and declared in the config; TRAIN-ONLY tree
    state asserted per row; any artefact induced over EVAL episodes is contamination (the p8a29/p2dca incident, 71%,
    recurred at ~70% in the multi-corpus line [LEDGER MC-E2E narrative; FW L229]).
(b) CHECKER OUTPUT TABLE. One row per (task, agent): a normalised OUTPUT (pass/fail vector, final-state diff, or an
    exact target), a checker table sha, a termination proxy VERSIONED like checker_answers_v2, and the reading rule
    fixed in the table's header. D_c (decidable share) is read under the STRICT reading = terminated AND
    checker-decided over ALL admitted episodes (cap-hit episodes stay in the denominator: rule 10). The MATH lesson
    is the reason the reading is fixed first: one table read 0.9840 / 0.8268 / 0.6701 [LEDGER CHECKER-ANSWER-INGEST].
    Reference_state for the cell is CHECKER_OUTPUT [FW L37]; a task specification, a step list or a process rubric
    is NEVER a reference (IFEval 0.658, ties 0.256, flips 0.38 [LEDGER GEN-ARENA]); a reasoning model's own
    trajectory as CACHED_SOLVE is not admissible until C5 sizes it and a REF-QUAL pass under one recorded protocol
    exists with a trajectory leakage audit, which does not (the n-gram audit has no trajectory analogue).
(c) TERMINATION AS A CLASS. finish_reason and completion_tokens per STEP and per EPISODE; the step cap and the episode
    cap (steps, tokens, wall-clock) declared per corpus at admission; a cap-hit episode is NON_TERMINATED - a class,
    never a verdict, never a tie, never dropped from the denominator [FW L236 guard 10; CONTEXT rule 10]; the
    admitted-population denominator printed on every row (STAGE3-MATH-CAPFREE's 9,307 of 11,144 form).
(d) THE JUDGED ARTEFACT. tool log + final state, under a stated per-episode artefact cap (tokens); per agent: deployment
    fingerprint, provider, response id, tokens, latency. Before any judged pilot: the item-19 per-model max_tokens probe
    on the trace-shaped prompt (50 calls per judge model [FW L372]) AND an input-side fit check - two artefacts + the
    checker output + the template must fit the judge's context; an artefact over the cap is a class (ARTEFACT_OVER_CAP),
    never silently truncated; a match with one is not judged.
(e) DESIGNED STRATUM. A (source, domain) stratum per task, because routing value lives at the family layer (+3.38pp
    clean [LEDGER MC-E2E]; leaves lose to domains as a router, -0.9 +- 0.3pp [LEDGER MC-LEAF]); the anchor is the
    terminal reporting unit (sub-anchor rows closed: PROFILE-TREE-ROBUST, KEY-SUBANCHOR-SCALE [CTX §5]).

The pilot (0 judge calls). 300 episodes drawn question-stratified over the corpus's designed strata and >= 3 agents,
checker run under (b)'s strict reading: D_c point with a Wilson interval per stratum and pooled; cap-hit share per
agent; extractor / normaliser reproduction on a 50-row hand-labelled subset >= 0.98. Admission for JUDGED cells
requires D_c >= 0.95 at the point per stratum (interval printed; the CHECKER-ANSWER-INGEST PASS-AT-POINT form). A
stratum under 0.95 is PREDICTIVE-ONLY for judged rows and keeps key-built rows on terminated episodes only, with the
terminated-share printed beside every number.

What "agent capability" is measured AS under this framework. Per task family (anchor) with an outcome checker: the
agent's CHECKER-BUILT accuracy row on terminated episodes with a question-bootstrap interval, at 0 judge calls (the
key is the verdict there [FW L37]; ORACLE-BOARD rho 1.000, 0 top-4 violations [LEDGER ORACLE-BOARD]); a band per agent
(above / below / unseparated) and the undominated set per family [FW L131]. The judge's product on such a corpus is
never the ranking: it is (i) a CALIBRATION board of the deployed recipe on the checker's cells, and (ii) a CANARY (§3
names both bills). No per-trajectory rank; no "better process" claim (a preference claim, refused [FW L249-250]); no
row below the family; where no checker exists, reference_state NONE and no fidelity object - the number is refused.
An agent whose episodes often hit the cap gets a profile of its short episodes, and the row says so.

Prediction. The first agent corpus fails on TERMINATION the way MATH did: cap-hit rows 12-19% per model [LEDGER
CHECKER-ANSWER-INGEST], 16.5% of question-pairs lost [LEDGER STAGE3-MATH-CAPFREE]; strict D_c < 0.95 in at least half
of its strata; judged cells PREDICTIVE-ONLY on day one; key-built rows publishable on the terminated population.
Enforcement clause (as registered): a corpus whose pilot D_c is under 0.95 in a stratum is REFUSED for judged cells
in that stratum and KEPT for key-built rows only; no edge pass is scheduled on it (guard 9's generative budget rule).
Falsifier of the admission test itself: a corpus that passes (a)-(e) and the pilot and whose FIRST judged pilot is
refused by the truncation guard (> 5% unparsed or non-terminated on the deciding subset), or whose full-run strict D_c
falls below 0.95 in a stratum that passed the pilot - the pilot was not predictive and the test is amended (pilot
size, stratification) by insertion before any further spend. UNDETERMINED is an outcome: a corpus with fewer than
120 EVAL episodes per stratum (the support rule for a row [plan §2 A8; FW L117]) is admitted for description only.
Cost. 0 calls for the admission; the item-19 probe 50 calls per judge before any pilot; a first judged pilot <= 4,000
matches; a full calibration board per corpus at the x12 shape crosses the rule (~9,000 matches, ~20,000 cce [FW L193])
and needs the author's go, as C7 states.
Closed lines: none reopened (no rubric, no specification reference, no gating, no trajectory reference).
