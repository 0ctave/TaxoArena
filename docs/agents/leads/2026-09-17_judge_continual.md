Frame. The author wants a framework that judges MODELS AND AGENTS continually and returns a capability profile. The record's judge is a verification-fidelity instrument: "Judge accuracy throughout this record means AGREEMENT WITH AN ANSWER KEY ... nothing here speaks to open-ended generation, where no key exists" (ledger §1 scope note, row 7). ## 1. What STACK-v2 measures, and what of it survives a trajectory

### 1.1 The instrument, in the record's own numbers

- Recipe: grok-4-1-fast-non-reasoning, v2 verify-first system template, "[Reference solution - produced independently, may be wrong]" block holding the cached grok-4-1-fast-reasoning JSON answer-only solve, clean bareq512 anchor rubric, dual order with TIE on flip, confidence recorded never gated, cap 8192, temperature omitted (CONTEXT §4 rule 5; plan Amendment 1 D2). 0.865 Mistral / 0.864 grok on R3's 944 key-decidable pairs (STACK-v2, JUDGE-SWAP, RECIPE-GROK); reasoning judge with the same reference 0.879 (J1-R), so the cheap stack sits 1.4pp under the reasoning ceiling.
- The value is the reference, and the reference's value is its correctness as an ANSWER: +12.6pp in the deployed pairwise format (0.864 vs 0.738, 144:25, p=1.6e-21; PAIR-NOREF); a checklist by the same model, no answer, is worth +1.6pp n.s. (0.749 vs 0.734) against the answer's +11.1pp, and BOTH vs REF +0.6pp [-1.5, +2.7] (REF-CHECKLIST, n=826, PRIMARY FAIL).
- The judge transcribes rather than reasons: showing the reference raises the REF contrast +1.811 [+1.507, +2.121] and lowers KEY -0.560 in the pointwise format (FORMAT-REF); in the pairwise format it adds +1.60 of reference-following without giving up correctness-weighting (PAIR-NOREF delta KEY -0.022 [-0.240, +0.191]). Agreeing with the reference vs being right: 2.7:1, an UPPER BOUND (CONSENSUS-FIT; the no-reference control still scores REF +0.507). Accuracy 0.922 when the reference backs the key-correct model, 0.657 when neither, 0.226 when it backs the wrong one (CONSENSUS-FIT, 6,049 key-decidable). Judge competence is irrelevant given the reference: 0.780 (judge solved) vs 0.796 (judge failed) when the reference is right (JUDGE-2x2).
- Ceiling: a PERFECT reference buys +16.4pp (0.612 -> 0.777, 55:6, p=5.4e-11) and acts only through reference correctness (reference-wrong stratum 0.146 -> 0.720, n=82; reference-correct 0.788 -> 0.797, n=217); the judge's IRREDUCIBLE error 0.223 is the larger half against reference-induced 0.165; 49 of the 67 residual errors are dual-order ties and 16 of the 18 committed errors went to the longer answer (ORACLE). Three levers sized and the frontier order still absent: reference +16.4, order balancing 13.5, tie resolution +8.0 (AGGREGATE).
- Most "accuracy" is decisiveness, not discrimination: on committed verdicts the reference is worth 0.929 vs 0.897, i.e. 74% of its value is the judge abstaining less (PAIR-NOREF); the anchor rubric is +1.5pp of decisiveness (p=0.044) and +0.2pp of discrimination (STACK-NORUBRIC); RK-1b's card ~86% abstention (RK-1b-GROK restatement); AGGREGATE's replicate tie-break +8.0pp is abstention alone.
- Noise floor: 5.7% test-retest on byte-identical prompts (DECOMP, 299 matches); 0.050 at temperature 0 vs 0.057, CI [-0.030, +0.017] (TEMP-0); no paired judge effect under ~3pp is readable from one pass (FRAMEWORK Limits). Session drift +0.8pp (RUBRIC-512-SS, cited in FRAMEWORK Stage 9). Position sensitivity is a property of CONTESTED matches: cross-tier flip 0.055 (below the floor) vs frontier 0.182 (POSITION-FULL).
- Length: causal and about demonstrated reasoning content, not bytes: truncating the correct answer's reasoning drops correct verdicts 0.766 -> 0.259 (183:1); padding null (L1); reasoning judge halves the drop (L1-R); the verify-first mechanics reduce it, drop 0.507 -> 0.421 -> 0.318 across L1, L1-V, L1-V2; an "ignore length" clause does nothing (H7 delta -0.007). Global coefficient +0.39 / 1k chars (z=14.6), rubric-invariant, cross-family (H3); on both-right pairs the judge takes the longer answer at +3.44 / 1k (TOPIC-DIFFICULTY C3 decomposition).
- Closed and not reopened here: rubric text at every granularity (RUBRIC, LADDER, RUBRIC-512-R, J6, RK-1, LEAF-POWERED, STACK-NORUBRIC); rubric-shaped references (REF-CHECKLIST); reference ensembles, gating, confidence, two references (ENSEMBLE-REF, J2-D, REF-CONF, ABSTAIN); escalation (ESCALATE-LLAMA-LAW: treatment +0.024 A / +0.000 B against a deciding 0.136; the gain is tie removal and larger on the control); temperature (TEMP-0); single and selective order (ORDER-1, SELECTIVE-ORDER); the frontier (FRONTIER, AGGREGATE, ORACLE).

For a trajectory the mapping is: the OUTCOME CHECKER's normalised output (tests passed, final-state assertion, exact target) is CHECKER_OUTPUT; a task spec, a process rubric, a list of required steps is the IFEval object, the worst reference the record has (0.658 with 25.6% ties and 38% flips, GEN-ARENA); a reasoning model's own trajectory on the same task is CACHED_SOLVE, which on MMLU-Pro is worth +12.6pp at the price of 2.7:1 reference-following. Design rule already on record and the one that transfers unchanged: "give a judge the checker's OUTPUT, never its specification" (GEN-ARENA memo; FRAMEWORK Stage 1 "the checker's normalised output, never its specification").

### 1.3 The verification-fidelity object that exists for trajectories, stated exactly

What exists: free-form MATH traces (terminated only) judged against an exact target. That is the only trace-shaped fidelity number in the record, and it is a CONDITIONAL one: it was read on the 83.5% of question-pairs where both traces terminated under the consistent cap proxy (cl100k >= 960 AND abrupt end; 9,307 of 11,144 admitted), after CHECKER-ANSWER-INGEST found lm-eval capped MATH generations at 1,024 tokens and 12-19% of eval-side rows of Llama-3.1/3.3-70B, Qwen2.5-72B/Math and others end at the cap (D_c 0.6701 on 18 models, 0.8189 [0.7935, 0.8433] on the 8-model cell; STAGE3-MATH HELD before any call, then re-registered cap-free).

What it does not show, in the run's own words (programme L4013-4015): "anything about the 297 non-terminated responses, which rule 10 keeps out of every verdict; and calibration, by design" (24 of 28 pairs established, 0 wrong, UB 0.117, nominal < 3).

What it means, adversarially: the target answer on MATH IS the key. The framework's own Stage 1 rule says that on a key-built cell "putting the key in the reference block is the ORACLE condition (+16.4pp), which is not the deployed condition". STAGE3-MATH-CAPFREE is therefore the ORACLE condition on a generative corpus: it establishes that a cheap judge can READ an exact checker on a free-form trace (0.958 vs ORACLE's 0.777 on the hardest MMLU-Pro subset, and 0.929 on committed verdicts there), not that judging measures anything the checker does not. Its product for the board is nil (the key is the verdict, rho 1.000 at 0 calls, ORACLE-BOARD); its products are a calibration board (UNDETERMINED by design at 24 established edges) and a canary.

### 1.4 What does NOT transfer to agent trajectories

1. No key, no number. The record's every published figure is fidelity against a key, a checker or a possibly-wrong reference (CONTEXT §1). An open-ended agent task with no outcome checker has reference_state NONE (0.738 on MMLU-Pro; ties 0.177) and no way to READ the resulting accuracy, because "accuracy" is defined against the key that does not exist. "Which trajectory is better" with equal outcomes is a PREFERENCE claim, which the record refuses by rule (Limits L250).
2. The verbosity mechanism is the trajectory's shape. L1's finding is that the judge rewards DEMONSTRATED REASONING CONTENT (truncation 0.766 -> 0.259; padding null). A trajectory is reasoning content by construction: more tool calls, more intermediate checks, more self-verification. The one mitigation that worked was giving the judge something to VERIFY (the final answer against a reference; L1-V2 drop 0.318 still), and it works on the FINAL ANSWER. A judge shown two trajectories with the same final state and a checker's pass has nothing left to verify and is back at the L1 baseline; the record predicts it will prefer the longer trace at roughly +0.39 to +3.44 / 1k chars (H3; TOPIC-DIFFICULTY both-right pairs). Nothing in the record has measured this on traces; §4 lead 5 is the instrument.
3. Termination. Agent trajectories are long. The MATH 1,024-token cap removed 16.5% of question-pairs and moved per-model checker accuracy by up to +0.10 on admitted rows (STAGE3-MATH-CAPFREE); rule 10 makes finish_reason length NON_TERMINATED, never a verdict, never a tie (FRAMEWORK guard 10). Two trajectories in one 8192-cap judge prompt, dual order, is not a configuration the record has probed; the judge cap is sized per model from a 50-question probe (FRAMEWORK Stage 4), a procedure listed under item 19 and not yet executed on a trace-shaped prompt.
4. Leakage grows with surface. A shared reference inflates whichever contestant mirrors it: the grok reference endorses the grok contestant on 68.7% of matches vs the ensemble's 41.3%, composition +0.116 = 148% of the apparent self-preference gap (DECOMP); a more accurate reference agrees more with the most accurate contestant BY CONSTRUCTION (REF-QUAL-KIMI-JSON gate 3 +0.071 on gemini; REF-QUAL-GATE3-COND: the correctness-conditional form does not decouple it). A reference TRAJECTORY has tool choice, ordering and phrasing to mirror, far more than a letter. The three-rule n-gram leakage audit (REF-CHECKLIST dropped 96 of 782 checklists) has no trajectory analogue.
5. Position and contestedness. Position bias is absent off the frontier (0.055 vs 0.182, POSITION-FULL). Agent matches with the answer-disagreement filter applied on checker output are contested by construction (only pairs whose outcomes differ are eligible, FRAMEWORK Stage 3), so dual order stays mandatory and the 16% tie share (AGGREGATE) is the floor to budget for.
6. Format. Pairwise decides, pointwise ranks (POINTWISE: pairs 0.864 vs 0.808, board rho 0.9930 vs 0.9790; does not replicate per anchor, POINTWISE-REPL 4:8); GRADE where checkable, COMPARE where discursive. With an outcome checker a trajectory is "checkable" and the checker itself is the grade; with none it is discursive and the pairwise format is the deployed one.
7. Cell dependence. Under STACK-v2 the only cell-dependent input is the anchor rubric, and 225 of the 314 two-candidate questions share the anchor, so a dual-cell arm posts the identical prompt on 72% of its targets (BOUNDARY-DISAGREEMENT). No agent-task taxonomy exists; the anchor rubric would not exist either, and STACK-NORUBRIC says it is worth -1.5pp A / -0.2pp B to remove.

## 2. Continual judging: what a pipeline must version, re-judge, and may reuse

### 2.1 The drift objects the record has priced

- Judge test-retest: 5.7% on byte-identical prompts (DECOMP); the canary's own floor is read at pass 2 on or after 2026-09-22 (CANARY-BASELINE: 300 frozen matches, hash 50af669ac6997f9f, 150 contested + 150 cross-tier, 600 calls per pass, 0 invalid; pass-1 descriptives contested tie 0.280 / flip 0.193, cross-tier tie 0.220 / flip 0.173; prediction 4-6% contested floor). FRAMEWORK Stage 9 sizes the alarm: one epoch of 300 has MDE ~2.7pp and power ~0.59 against a 3pp drift; three pooled epochs (~1,000 decidable) MDE ~1.5pp.
- Provider nondeterminism as a DENOMINATOR effect: identical bytes (600/600 posted-byte sha equality) gave A -1.1pp [-3.2, +0.7] but B -2.6pp [-4.7, -0.6] on n=276, carried by WHICH matches each arm committed on (both-committed discordance 0:2), FAIL as registered (JUDGE-WIRING); at whole-board scale the same two instruments agree A +0.4pp [-0.2, +1.0], B +0.2pp on 4,495 key-decidable (JUDGE-WIRING-BOARD). Rule this yields: a re-judge is never read on convention B alone at n in the hundreds; both conventions, identical matches, question-clustered CI, and any difference inside ~1.9pp on <1,000 matches is the floor.
- Reference vintage: the reference of record (judge_solve/grok-reasoning.db, 3,432 of 3,445 pool questions, 13 content-filter rejections) carries no model id, prompt hash, protocol, cap or temperature (FRAMEWORK Stage 1; guard 19 "the existing canary sees judge drift only"). Two same-model re-solves agree 94% and each is right 35% on disagreements (REF-SC), which is the null for canary arm B (200 frozen questions re-minted every four epochs, alarm below 0.89). Arm B has never been run; the reference vintage has never been compared to anything.
- Content-filter refusals: deterministic per question, HTTP 400, cached as finish_reason content_filter and never re-posted (CONTEXT rule 10; JUDGE-FINISH-AUDIT). Counts on record: 13 pool questions with no reference; 17 of 569 Kimi solves (REF-QUAL-KIMI-JSON); 1 in 1,600 (NEWCOMER-PLACEMENT-LIVE); 1 in 18,246 (JUDGE-WIRING-BOARD); 1 in 782 checklists (REF-CHECKLIST); ARENA-V2 lost questions 4389 and 6528 to the class before it was cached. They stay in the guard denominator forever.
- Cap and population: the cap is part of the population definition. Raising it mid-cache is forbidden (my own rules); a provider or harness change to max output changes D_c (0.9840 -> 0.8268 -> 0.6701 across three readings of the same MATH table, CHECKER-ANSWER-INGEST) and therefore which pairs exist. The cap proxy (cl100k >= 960 AND abrupt end) is itself a versioned artefact (checker_answers_v2).
- Re-draw fragility of the certificate: two draws of the same judge on the same bytes put b1's established-label identification on opposite sides of the 3.84 line (GROK-CALIB dDev 4.47 identified; Kotlin draw 2.26 not) at ~26 events (JUDGE-WIRING-BOARD). A continual pipeline that refits the widener each epoch will grant and withdraw ORDERED-JUDGED from epoch to epoch on the same judge. The pending amendment (programme L4262-4266): pool both draws' established labels (~52 events) or print a power statement beside the identification. Item 26 is not yet amended.
- Judge finish provenance: 51 of 58 caches of record cannot distinguish NON_TERMINATED from wrong; every board of record is among them (JUDGE-FINISH-AUDIT). Forward-only: call_judge_full now returns finish_reason and the response id.

### 2.2 What must be versioned (the deployment fingerprint the record already names)

Per verdict row: judge model, deployment fingerprint, prompt hash (template + rubric + reference bytes), max_tokens, temperature (omitted, recorded as omitted), finish_reason, completion_tokens, provider response id, batch_id, order (FRAMEWORK Stage 4, guard 10). Per reference row: reference_model, fingerprint, prompt_hash, protocol_id (json answer-only), max_tokens, finish_reason, completion_tokens, minted_at, side_at_mint (Stage 1). Per population: pool id, cap proxy version, checker table hash, D_c per cell. Per fit: (board, judge) with the prior declared (K-RECONCILE: DEFAULT_PRIOR_STRENGTH 0.5 shrinks per-anchor theta SD 1.23-1.82x). Guard 11: caches differing on (model, fingerprint, prompt_hash, protocol_id, max_tokens, temperature) are never compared; guard 12: filtered/unfiltered, referenced/reference-free and different judges never share a fit.

### 2.3 What must be re-judged, and what may be reused

Re-judge triggers the record supports: (a) fingerprint change of the judge (a new judge = ~2,100 calls paired non-inferiority on the 944 R3 pairs + ~20,000 cce calibration board, "the most expensive update in the system", FRAMEWORK Online operation); (b) reference vintage change on a question (re-minted reference = new prompt bytes; the old verdicts enter as a separate vintage component, never pooled); (c) canary alarm (freeze publication for the epoch, hold batches; Stage 9). Not a trigger: a change of TREE. Verdicts under STACK-v2 depend on the tree only through the anchor rubric (BOUNDARY-DISAGREEMENT), and the rubric is +0.2pp of discrimination (STACK-NORUBRIC), so a re-celled question's verdicts are reusable if the rubric is held fixed or dropped; a re-celling changes the FIT, not the verdicts. Not a trigger: provider re-draw alone (JUDGE-WIRING-BOARD: same instrument within the floor).

Reusable forever: the cached reference solve (one vintage, until arm B alarms), every verdict row keyed on (match, prompt bytes, fingerprint), every refusal row, the established-label set per board (to be pooled across draws once item 26 is amended). New model: keyed cells 0 calls; ~3,100 cce for profile coverage at the x20 density; 400 matches is NOT a placement budget (7 and 3 key-tier bands, NEWCOMER-PLACEMENT-LIVE). Model DRIFT (same name, new weights) has no test in the record; it is a new model by answer content, see §4 lead 3.

## 3. Today's three findings, read for a judge that runs continually

### 3.1 TOPIC-DIFFICULTY (zero calls; MISTRAL-MERGED 21,536 verdicts, 2,811 q; x12, GROK-CALIB, Kotlin replications)
Key-decidable accuracy A falls 0.938 -> 0.783 (-15.5pp [-18.5, -12.4]) and ties rise 0.035 -> 0.101 (+6.6pp) from the easy to the hard tercile within anchors; the reference-correct rate falls 98.4% -> 93.7% -> 77.7%; holding it fixed the drop is -4.3pp (72%), holding within-reference accuracies -12.2pp (79%); the judge's own residual within reference-correct is -4.5pp [-6.7, -2.5]. Every difficulty-stratified board is UNDETERMINED (nominal < 3 in 42 of 42 strata). The key-free plurality proxy has Spearman 0.785 with difficulty and recovers 44% of the contrast, with no edge-level test.
Consequence for continual operation: the per-question REFERENCE-CORRECT probability is the dominant quality term of a judged cell, inside a cell as across cells (REF-BY-CELL 0.727-0.952). A monitor that watches judge accuracy per cell watches mostly the reference; the thing to version and monitor per cell per epoch is the reference's correctness on keyed audit mass. On an agent corpus without a key, the only key-free instrument the record has for "this cell got harder" is the plurality proxy, and it is consensus-shaped (the same object DECOMP names as leakage). Its use as a widener covariate needs its own registration (the outcome's stated consequence).

### 3.2 BOUNDARY-DISAGREEMENT (zero calls; merged board 21,519 matches, 2,808 q)
Lowest-margin quintile: ties -0.2pp [-2.4, +2.1], flips +0.4pp [-1.3, +2.1]; leaf-FE flip coefficient -0.024 [-0.074, +0.025]; wrong(established) no difference; MULTI-OWNERSHIP closed as a judging mechanism. The x12 schedule alone reads a flip gradient +2.7pp [+0.4, +5.2] the merged null averages away (C2 "not shown rather than shown absent"). Under STACK-v2 the only cell dependence is the anchor rubric and 72% of two-candidate targets share it.
Consequence: the judge is cell-independent in practice. For a continual pipeline that is a reuse dividend (§2.3): a tree epoch (EPOCH-NULL, FRAMEWORK item 15) does not invalidate verdicts, only fits. For agents: there is no evidence that a per-task-family judge would differ from a generic one; the rubric line's closure (rubric 0.761 generic / 0.774 anchor / 0.757 stratum / 0.770 leaf, LADDER; RUBRIC-512-R 24:24) is the prior for any "agent-task rubric" proposal, which is a closed line unless it brings a data-only, checker-derived card rather than prose (RK-1b +1.7pp, RK-1b-GROK +1.3pp p=0.073, Holm 0.35, ~86% abstention).

### 3.3 CAP-GATE-POSTHOC (exploratory, zero calls, zero constructions)
A capability split gate accepts a DIFFERENT SET from the geometric certificate (af t=+1: 24 of 69 accepted, 9 of 16 certified, Jaccard 0.29); certified-vs-uncertified contrast +1.20 is mostly site size (matched on log n +0.31); the strongest "different sites" do not replicate on the tree's own held-out side. Nothing about any board or the judge changes. Consequence for a continual capability profile: the anchor stays the terminal reporting unit (PROFILE-TREE-ROBUST, KEY-SUBANCHOR-SCALE closed; anchor R 0.67-0.72 [0.61, 0.83], ~210 questions per cell for 0.70); a capability-gated construction would be an additive admission rule, not a new profile row. An "agent capability profile" inherits this: rows at the task-family (anchor) level, with an interval, and nothing below it.

## 4. Leads: registrable tests toward agent judging and continual operation, ranked by value per call

### 4.0 The adversarial statement first: where "judging agents" is not a measurable object

- No agent corpus, no trajectory, no tool log and no code test exists in the record. The union is MMLU-Pro, BBH, MATH, IFEval, MuSR, GPQA (multi_corpus_design.md L199); its only free-form traces are MATH (with a 1,024-token harness cap) and IFEval responses.
- Where an outcome checker exists, the framework publishes the board from the checker at 0 judge calls (Stage 1: "the key is the verdict there"); judge calls buy a calibration board and a canary only. STAGE3-MATH-CAPFREE 0.958 / 0.993 is that calibration read, in the ORACLE condition.
- Where no checker exists, reference_state is NONE (0.738, ties 0.177 on MMLU-Pro) and there is no key to read accuracy against; the framework refuses the number (Limits L249, L250).
- The only middle regime the record has measured, a partial or specification-shaped reference, is the worst result in the programme (IFEval 0.658, ties 0.256, flips 0.38).
- Therefore "agent capability" as this framework can measure it today is: per task family with an outcome checker, the model's checker-built accuracy row with its interval (0 judge calls), plus the judge's verification fidelity on the SAME cells as a calibration and canary. What a judge would add on unchecked trajectories (process quality, efficiency, safety) is a preference claim outside the record. Every lead below is sized to widen that boundary by a measurable step, not to cross it.

### Lead 1 (0 calls) RE-JUDGE-RULE + ITEM-26-POOLED: the continual re-judge budget rule and the pooled-draw identification
- Question: does pooling the established labels of the two existing draws of the same judge (GROK-CALIB, Kotlin c0d3f708cbc3930e; 9,123 common matches) identify b1 at ~52 events, and what re-judge triggers does the record support?
- Instrument: systematic_budget's established-label refit on the pooled labels, dDev vs b1 = 0 at 3.84, LOAO wrong(established) with nominal, both draws' single-draw values printed beside (4.47 / 2.26). A registered rule text: re-judge on fingerprint change, reference vintage change, canary alarm; never on tree re-celling or provider re-draw; every re-judge read on identical matches, both conventions, question-clustered CI, floor 1.9pp below 1,000 matches.
- Hygiene: caches read mode=ro; denominators 891 / 920 edges as registered; no new calls.
- Criteria: dDev pooled >= 3.84 -> ORDERED-JUDGED available for grok on pooled labels; < 3.84 -> a power statement is mandatory beside every identification and the fallback stands. Prediction: pooled dDev between 3.5 and 5.5, identified; LOAO wrong 2-4 (established 1-2), nominal ~2.2, calibration UNDETERMINED. Falsifier: pooled dDev < 2.5.
- Value per call: infinite (zero calls); it closes the one pending amendment that makes a continual certificate flap between epochs. Closed lines untouched.

### Lead 2 (0 calls) REF-QUALITY-MONITOR: reference correctness per cell per epoch as the continual quality signal, and the plurality proxy's edge-level test
- Question: is per-cell reference-correct rate (on keyed audit mass) a sufficient statistic for per-cell judge quality across the boards of record, and does the key-free plurality proxy predict wrong(established) edges out of sample?
- Instrument: on x12 MAIN, GROK-CALIB, Kotlin and x20 (four caches, same questions): per (anchor, epoch-proxy = cache) reference-correct rate vs key-decidable accuracy A and B; the TOPIC-DIFFICULTY decomposition per cell; then the plurality proxy as a per-edge covariate in a LOAO fit beside A (the widener's agreement predictor), wrong(established) at matched utility. This is the registration TOPIC-DIFFICULTY's consequence names.
- Hygiene: readout-time artefact (46-model key accuracy is an EVAL-side, judgment-time quantity, nothing induced); no key input at inference for the deployed fit (systematic_budget's rule) - the proxy is the only deployable form; never a GATE (closed: gating on reference agreement, ABSTAIN, REF-CONF).
- Criteria: (1) Spearman(reference-correct rate, accuracy A) across 14 anchors x 4 caches >= 0.8; (2) proxy covariate: established wrong calls at matched utility not above the A-only widener, LOAO. Prediction: (1) holds ~0.85-0.95; (2) UNDETERMINED (nominal < 3 on every board in reach, FRAMEWORK Limits). Falsifier: (1) < 0.5.
- Value: zero calls; defines the one per-cell continual monitor the record's own decomposition licenses. Hazard: the proxy is consensus-shaped; it monitors, it never gates.

### Lead 3 (0 judge calls; contestant generation cost only) MODEL-VINTAGE-CANARY: model drift as answer-content drift
- Question: the record has no test for a model whose name is constant and whose weights change. Define drift by content: regenerate each roster model's answers on the 300 canary questions (279 distinct, CANARY-BASELINE set) per epoch; extracted-answer agreement with the model's cached vintage; alarm below the REF-SC null (0.94 - 3 sqrt(0.94 x 0.06 / n)).
