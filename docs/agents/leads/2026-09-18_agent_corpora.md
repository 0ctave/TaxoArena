# Agent corpora with precomputed traces: admission survey for a TaxoArena agent extension

Date: 2026-09-18. Web survey only; nothing in the repository was touched. Everything below is what is downloadable today (verified by fetching the listing or the card), not what a paper promises. Where a fetch did not show a number, the entry says so.

Admission schema (from the record): (a) task stem + stable content key + family_id for templated tasks; (b) checker emitting a normalised OUTPUT per (task, agent) so the reference costs zero and the answer-disagreement filter applies; (c) per-step finish_reason / completion tokens or at least a recorded step/turn cap; (d) tool log + final state as the judged artefact with a stated cap; (e) designed (source, family) stratum; (f) >= 8 agents on the SAME tasks, public, licensed; (g) >= ~600 tasks (cells of 60-140).

Scoring key: PASS / PART / FAIL / ? (not verifiable from what is downloadable).

## 1. Per-corpus detail

### 1.1 HAL, Holistic Agent Leaderboard (Princeton)
- Paper: https://arxiv.org/abs/2510.11977 — "21,730 agent rollouts across 9 models and 9 benchmarks", "2.5B tokens of language model calls", "about $40,000"; logs released "to incentivize further research into agent behavior". Benchmarks (Table 3): Online Mind2Web, AssistantBench, GAIA, CORE-Bench Hard, ScienceAgentBench, SciCode, SWE-bench Verified Mini, TAU-bench Airline, USACO. Models: Claude Opus 4.1, Claude 3.7 Sonnet, o3, GPT-4.1, GPT-5, o4-mini (low/high), DeepSeek R1, DeepSeek V3, Gemini 2.0 Flash. Scaffolds per benchmark: BrowserUse/SeeAct, Open Deep Research, CORE-Agent/Generalist, SAB Self-Debug, SciCode Tool Calling, SWE-Agent/Generalist, Generalist (tau few-shot removed for leakage), USACO Episodic+Semantic. "ScienceAgentBench averages $13 per evaluation. ... Online Mind2Web averages over $450."
- Harness: https://github.com/princeton-pli/hal-harness — `hal-decrypt -D dir` / `-F file.zip`; UPLOAD json has config, results, raw_eval_results, raw_logging_results (Weave call traces), total_usage, total_cost; get_metrics must return accuracy, successful_tasks, failed_tasks (task-id lists). Decryption password is hardcoded in https://raw.githubusercontent.com/princeton-pli/hal-harness/main/hal/utils/decrypt.py (`JsonEncryption("hal1234", ...)`), so the encryption is anti-scraping only.
- Traces: https://huggingface.co/datasets/agent-evals/hal_traces — 113 GB, "No dataset card yet", no licence field, 625 commits, encrypted zips named `<benchmark>_<timestamp>_UPLOAD.zip`, grouped by benchmark and model (AssistantBench ~45 files, Browser-Use ~16, CoreBench...). Individual files 14 MB - 1.6 GB.
- Leaderboard pages give per-run totals: SWE-bench Verified Mini (50 tasks) https://hal.cs.princeton.edu/swebench_verified_mini — SWE-Agent + Claude Sonnet 4.5 High 72% at $463.90; Opus 4.1 High $1,599.90; GPT-5 Medium $162.93; note "reasoning token budgets set at 1,024 (low), 2,048 (medium), and 4,096 (high) for non-OpenAI models". TAU-bench Airline (50 public test tasks) https://hal.cs.princeton.edu/taubench_airline — 26 configurations, $0.31 to $180.49 per full run; few-shot agent removed for "a critical data leakage issue".
- Task counts per benchmark are those of the source benchmarks (GAIA validation 165 https://huggingface.co/datasets/gaia-benchmark/GAIA ; tau airline 50; SWE Mini 50; the rest 33-307), i.e. no single benchmark reaches (g); only the union (~1.15k) does, and the union mixes checker types: exact match (GAIA), unit tests (USACO, SciCode, SWE), numeric prediction intervals (CORE-Bench), program-output scoring (ScienceAgentBench), DB state (tau) and an LLM judge (Online-Mind2Web, WebJudge) — the last one is NOT a checker and must be excluded under (b).
- Score: (a) PASS, (b) PART, (c) PART, (d) PASS, (e) PASS, (f) PASS per benchmark, (g) PART.

### 1.2 SWE-bench / SWE-bench Verified experiments
- https://github.com/SWE-bench/experiments (README https://github.com/swe-bench/experiments/blob/main/README.md): each submission = all_preds.jsonl, logs/<instance_id>/{patch.diff, report.json, test_output.txt.gz}, trajs/<instance_id>.*, results/ (resolved ids). Trajectories: "Human-readable text-based files ... generated during inference, not post-hoc ... one file per task instance" in any text format. Download: `python -m analysis.download_logs evaluation/<split>/<submission>` from `s3://swe-bench-submissions/` — an AWS account and CLI are required. Newer entries (mid-2026 on) point to submitter-controlled repos via metadata.yaml `assets`.
- Count: the GitHub API listing of evaluation/verified shows 139 submission directories (20231010_rag_claude2 ... 20250725_sweagent_devstral_small_2507) https://api.github.com/repos/SWE-bench/experiments/contents/evaluation/verified ; sample metadata https://raw.githubusercontent.com/SWE-bench/experiments/main/evaluation/verified/20250725_sweagent_devstral_small_2507/metadata.yaml lists `trajs: s3://swe-bench-submissions/verified/.../trajs`, `checked: true`, `os_model: true`. Many entries are proprietary scaffolds with no trajs (the Trajs column on swebench.com is per-entry). The experiments repo has no LICENSE file (raw LICENSE 404).
- Scoring: (a) PASS (instance_id; family = repository, 12 repos in Verified); (b) PASS (report.json FAIL_TO_PASS/PASS_TO_PASS is a normalised pass/fail vector); (c) ? (each submitter's own cap; SWE-agent .traj records exit_status, OpenHands records max_iterations but neither is guaranteed); (d) PART (format varies by submitter; a normaliser per scaffold is needed); (e) PASS; (f) PASS; (g) PART (500).
- Hazard specific to this corpus: the same model appears under many scaffolds, so "agent" = (scaffold, model) and the number of distinct agents with a full trajs/ set for all 500 instances must be verified per entry before the pairwise design is fixed.

- Submission format (https://raw.githubusercontent.com/multi-swe-bench/experiments/main/README.md): logs/[org]/[repo]/evals/pr-[id]/{fix.patch, fix-patch-run.log, report.json}; trajs one text file per instance with the instance id in the filename; experiments repo Apache-2.0.
- Paper (https://arxiv.org/html/2504.02605): 1,632 instances: Java 128, TypeScript 224, JavaScript 356, Go 428, Rust 239, C 128, C++ 129; Python 460 from SWE-bench; 9 models x 3 methods (MagentLess, MSWE-agent, MopenHands = OpenHands CodeAct v2.1); evaluation by run.log/test.log/fix.log with FAIL_TO_PASS transitions; Table 8 per-issue cost: DeepSeek under $0.03, OpenAI-o1 $0.64-$3.75 depending on language; MagentLess cheaper than the agentic methods. ### 1.4 tau-bench / tau2-bench (Sierra)
- Repo https://github.com/sierra-research/tau2-bench (MIT). Domains airline 50, telecom 114, retail 114, banking_knowledge 97 = 375 tasks (paper https://arxiv.org/pdf/2506.07982 gives 50/114/114; banking added later). Checks: database state, actions, communication; pass^k metric; simulation results contain messages, tool calls, reward_info.
- Leaderboard submissions (https://github.com/sierra-research/tau2-bench/blob/main/docs/leaderboard-submission.md): 4+ trials per domain; submission.json in repo; trajectories are uploaded by maintainers to `s3://sierra-tau-bench-public/submissions/<dir>/trajectories/`.
- Public bucket listing (https://sierra-tau-bench-public.s3.amazonaws.com/?prefix=submissions/&max-keys=400): 23 submission dirs, 11 with trajectories/ (e.g. claude-3-7-sonnet_anthropic 3 files ~76 MB; claude-opus-4-5_sierra 4 files ~195 MB; claude-opus-4-6, -4-7 (~326 MB), -4-8, claude-opus-5, claude-fable-5, claude-sonnet-4-5_sierra, gemini-2-5-pro_sierra, plus a voice submission with WAV audio); 7 vendor submissions (claude-opus-4-1_anthropic, claude-sonnet-4_anthropic, deepseek-v3.2, distyl-buttonagent...) have NO trajectories. Site https://taubench.com/ shows tau2 text leaders (Qwen3.5-397B 87.9%, Gemini 3.0 Pro 85.4%, Claude Opus 4.5 85.3%) — those top entries are not among the ones with public trajectories.
- Scoring: (a) PASS; (b) PASS; (c) PASS (max_steps in config, termination reason in sim JSON); (d) PASS; (e) PASS (domain; within-domain the tasks are templated on the policy document, so family = policy clause is a needed extra key); (f) PART (9-11 agents with trajectories, most run by Sierra on the same tau2 code, but different agent classes/dates); (g) FAIL (375 tasks; x4 trials gives 1,500 episodes but the SE rule counts distinct tasks).

[CORRECTED 2026-09-27 by INCONSISTENCIES-PASS (RP01, A4): 109, not 158 (as the L15 bracket)]
- Score files (https://raw.githubusercontent.com/HuanzhiMao/BFCL-Result/main/2025-12-16/score/claude-sonnet-4-5-20250929-FC/multi_turn/BFCL_v4_multi_turn_base_score.json): line 1 `{"accuracy": 0.69, "correct_count": 138, "total_count": 200}`; then one record per FAILED entry with id, valid=false, error (expected vs actual state, e.g. "instance state mismatch"), model_result_decoded, possible_answer, inference_log. - Caveat: episodes are short (a few turns, tens of calls), so the "long trace" hazards are mild, but this also makes it the cheapest possible pilot for the checker-as-reference regime.

### (2) Top candidate for "we compute traces ourselves" and the price per agent-run

- Recommendation: BFCL multi_turn (800 entries) if the aim is the cheapest defensible pilot; tau2-bench (375 tasks, MIT, deterministic DB-state checker, user simulator included) if the aim is a customer-service capability profile; Multi-SWE-bench or SWE-bench Verified with mini-SWE-agent if the aim is the coding cell. Cost anchors, all from published runs:
  - SWE-bench Verified Mini (50 tasks, SWE-agent, HAL): GPT-5 Medium $162.93 -> $3.3/task; Claude Sonnet 4.5 $463.90-$505.92 -> ~$10/task; Claude Opus 4.1 $1,351-$1,600 -> $27-32/task; o4-mini $248-259 -> ~$5/task (https://hal.cs.princeton.edu/swebench_verified_mini). Steps: Claude Sonnet 4.5 averaged 47 steps vs 32 for its predecessor on SWE-bench Verified (search summary, https://caylent.com/blog/claude-sonnet-4-5-highest-scoring-claude-model-yet-on-swe-bench).
  - Multi-SWE-bench Table 8: DeepSeek < $0.03 per issue; OpenAI-o1 $0.64-$3.75 per issue; MagentLess cheaper than the agentic scaffolds (https://arxiv.org/html/2504.02605).
  - tau-bench airline (50 tasks, HAL): $0.31 (Gemini 2.0 Flash) to $180.49 per full run; o4-mini High $11.36 -> $0.23/task; Claude 3.7 Sonnet generalist $42.11 -> $0.84/task (https://hal.cs.princeton.edu/taubench_airline). Add the user-simulator model's calls (same order of magnitude).
  - HAL overall: $40,000 / 21,730 rollouts = ~$1.84 per rollout; 2.5B tokens / 21,730 = ~115k tokens per rollout (https://arxiv.org/abs/2510.11977). ScienceAgentBench $13 per full evaluation (102 tasks -> ~$0.13/task); Online-Mind2Web > $450 per evaluation (300 tasks -> ~$1.5/task, LLM-judged).
  - BFCL multi-turn: no official cost figure; entries are a few turns of function calls with a 20-step cap, so tens of thousands of tokens per entry at most, i.e. cents per entry for a cheap model and well under $1 for a frontier model (estimate, not a published number).
- Pricing rule for the author: N agents x M tasks x (cost/task from the table) x trials; e.g. 8 agents x 800 BFCL entries x ~$0.10 = ~$640 at 1 trial; 8 agents x 375 tau2 tasks x ~$0.5 x 4 trials = ~$6,000 plus simulator; 8 agents x 500 SWE-bench Verified x ~$5 = ~$20,000 (mini-SWE-agent with mid-tier models). The judge cost on top is the record's usual two calls per pair.

### (3) What the taxonomy would be built on, and the split hazard

- Coding corpora (Multi-SWE, SWE-bench): the task text is the issue statement plus the repository identity; a taxonomy built on issue text alone will rediscover repositories (repo is the dominant cluster) — that is the routing signal the record already shows lives at the family layer, so family_id = repo and the split must be by repo or by instance-within-repo with the repo held constant across sides (the record's rule: construction never sees eval tasks; for templated families, a family wholly on one side).
- BFCL multi-turn: the stem is the scenario dialogue plus the tool schema (the function docs are part of the input); the four augmentations of one base scenario share the stem, so family_id = base index and the split is by base scenario. Building the taxonomy on tool-schema text instead of dialogue text gives a different (API-domain) tree; both are legitimate but the choice must be registered.
- tau2: tasks are generated from a domain policy + user persona; the taxonomy would be built on task instruction + policy clause; families are policy clauses, and the four trials of a task are replicates, never separate items.
- HAL / cx-cmu multi-benchmark unions: the benchmark itself is the stratum; a taxonomy over the union of task texts will separate benchmarks first (as the record saw domains beat leaves as a router). Use the benchmark as the designed (source, family) stratum and build leaves within it.
- Judged artefact: the tool log (calls + observations) plus final state (patch / DB diff / backend state), truncated under a stated cap; never the screenshots (OSWorld) or the free-text reasoning_trace (GAIA).

### (4) Hazards the record predicts

- Non-termination classes: every corpus has a cap (BFCL 20 steps/turn, OpenHands max_iterations 100, OSWorld 15/50/100, Terminal-Bench timeouts, AgentRewardBench 40k/8k tokens, HAL reasoning budgets 1,024/2,048/4,096) but only OSWorld, tau2 and cx-cmu record the termination cause as data; ATIF explicitly has no finish-reason field; SWE-bench trajs depend on the submitter. The MATH lesson (a 1,024-token cap silently cost 16.5% of pairs) will recur in the BFCL long_context category and in the 15-step OSWorld files; cap-hit episodes must be a class, not a loss.
- The checker IS the reference: with a pass/fail vector on both sides, the judge's product is calibration against the checker (a canary), not new information; the value is where checkers are known to be wrong — AgentRewardBench measured 55.9% rule-checker recall on WebArena, tau2 outcome eval passes trajectories that violate policy (llmcontract-tau2 https://github.com/chrisbartoloburlo/llmcontract-tau2), TheAgentCompany gives partial credit — and on same-outcome pairs (both pass / both fail), where the record's disagreement filter removes the pair and the judge would be ranking process, which the record has not validated.
- Length bias on long traces: the record's +0.39 per 1k chars applies to traces of 100k+ tokens (HAL average ~115k tokens per rollout); a text judge cannot read whole traces, so the judged artefact must be a fixed-budget projection (final state + last-k calls) and length-matched pairs are mandatory for any ordering claim.
- Agent identity: "same agent" means (scaffold, model, config, date). Terminal-Bench's 40 entries are ~25 scaffolds; SWE-bench's 139 entries are mostly one-off; only Multi-SWE (3 scaffolds x 9 models), BFCL (one harness, 158 models), TheAgentCompany (OpenHands 0.14.2 x 10) and HAL (one scaffold per benchmark x 9-12 models) hold the scaffold fixed. [CORRECTED 2026-09-27 by INCONSISTENCIES-PASS (RP01, A4): 109, not 158 (as the L15 bracket)]
- Contamination and leakage: HAL removed tau few-shot results because demonstration files contained test examples; SWE-bench Verified instances are in training sets; a taxonomy built on eval tasks is the record's pool-mismatch incident again.
- Licence gaps: HAL traces carry no licence on the card; SWE-bench experiments repo has no LICENSE; cx-cmu is gated with no licence; AgentRewardBench is a fair-use declaration. Multi-SWE (CC0), BFCL (Apache-2.0), tau2 (MIT), OSWorld trajs (MIT), Terminal-Bench (Apache-2.0), Toolathlon (CC-BY-4.0) are clean.
- Size: OSWorld 500 GB and HAL 113 GB are download-and-filter jobs; Multi-SWE 4.7 GB and BFCL tens of MB per model are laptop-scale.
