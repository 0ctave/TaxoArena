## Ruling on the accounting reading (item 5)
The ruling's "(i) ... counted from its OWN cache plus its ledger rows" must be read as "both sources are consulted and the LARGER counts", as the builder coded it. It must not be read as an arithmetic sum. The ledger counts every posted call, errors included. The cache counts 2 x rows, with errors never cached. So whenever every launch appended its row, ledger >= cache, and max() returns the exact posted count. A sum would count each cached call twice: after TRACE's pilot (24) and run (2136) it reads 4320, not 2160, and would refuse a legitimate retry. max() under-counts only after a hard crash that skips `finally`. It then misses that launch's errored and in-flight calls, never its cached rows, which is why the cache is consulted at all. That residual is D10. The (iii) margin (6,220 of 14,000 at the dry-run) makes it immaterial for the combined statement.
